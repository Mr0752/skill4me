## 三、卖点（核心功能，列点）

- **零依赖、可扫任意小程序**：一条 `node audit-redlines.js <目录>` 跑完，不需要装任何包。
- **真机才暴露的坑也查**：可选链 `?.`、空值合并 `??`、逻辑赋值 `||=` 这些模拟器不报、真机直接白屏的语法，全部标红。
- **tabBar 跳不动、列表错乱**：`navigateTo` 跳 tabBar 静默失败、`wx:key="index"` 列表更新错乱，交叉核对 `app.json` 自动判定。
- **云开发额度守护**：`setInterval` 盲轮询嫌疑、定时器未清理（`onHide` 不 `clearInterval` 会后台狂烧配额）精准提示。
- **性能红线**：整页 / 大对象 `setData`、`setData(this.data)`、直接改 `this.data` 不刷视图，一并揪出。
- **实验性 WXML 启发式**（加 `--strict`）：`{{}}` 方法调用 / 中文键、`<b>` 组件等编译期静默失效项。
- **页面四件套完整性**：`audit-paths.js` 一键校验 `pages` / `subPackages` 里每个页面 `.js/.json/.wxml/.wxss` 四件齐全，并揪出"目录有 wxml 却没在 app.json 注册"的漏网孤儿页面；四级排除机制消除噪音（内建目录 / 项目根 `.redlineignore` / `--ignore=a,b` / `<include>`·`<import>` 片段自动识别）。
- **四层交互闭环**：`audit-closure.js` 扫出导航闭环（目标页存在 + API 与页类型匹配 + 绝对路径）、事件闭环（wxml 绑定的 `bindXxx`/`catchXxx` 在对应 JS 真实存在）、数据闭环（Storage 写入键都有读取、死键归零）、孤儿页（无入口的死页）；业务强相关项（导航封装名、Storage 读写正则、键前缀）在脚本顶部 `CFG` 配置，按项目改、不改逻辑。
- **每条带红线 id + 修法 + 前后代码对照**：报告按严重度分组，条目定义见 `references/redlines.md`，逐条怎么改照抄 `references/fix-examples.md` 的"修复前 → 修复后"示例，可当提审前体检清单。
- **异常处理友好**：目录传错、文件读不了、node 缺失都有明确中文提示；退出码 0 / 1 / 2 可直接当 CI 提交闸门；跑不起来、误报边界见 `references/faq.md`。
- **纯本地零依赖**：不联网、不上传代码、不需要 npm install，一条 node 命令直接跑。

## 四、为什么值得装（价值主张）

> 小程序提审被拒、上线后真机白屏、云函数额度一夜烧光——90% 来自同一批“模拟器测不出、lint 不报”的红线。
> 这个技能把这些坑做成一个可重复跑的体检脚本：改完代码跑一遍，硬性红线清零再提审，把事故挡在发布前。

- 接手老项目、不确定历史代码踩了哪些坑的维护者。

## 六、使用方式（示例）

```
# 审计当前目录
node audit-redlines.js

# 审计指定小程序根（可一次传多个）
node audit-redlines.js miniprogram cloudfunctions

# 额外启用实验性 WXML 启发式（易误报，仅参考）
node audit-redlines.js miniprogram --strict

# 查看用法
node audit-redlines.js --help
```

退出码：`1` = 仍有硬性红线（必须修）；`0` = 硬红线清零（建议项仍需人工复核）；`2` = 目录/参数错误（可直接当 CI 闸门）。

**输出示例（真实运行结果）**：

```
审计完成：1 个 JS + 1 个 WXML（已交叉核查 app.json 的 tabBar）

【硬性红线 4 条 · 必须修】
  [红线2-1] pages/index/index.js:3  可选链 ?.  → a?.b → (a||{}).b
  [红线9-1] pages/index/index.js:6  navigateTo 跳 tabBar 页面「pages/me/me」（静默失败，应用 switchTab）  → 改用 wx.switchTab 或封装 goPage
  [红线8-3] pages/index/index.wxml:1  wx:key="index"（列表更新错乱）  → 改用唯一字段或预生成 _k

【建议复核 5 条 · 人工确认（可能误报）】
  [红线1-1] pages/index/index.js:4  setInterval 盲轮询嫌疑  → 改递归 setTimeout + 无变化退避
  [务必3-1] pages/index/index.js:5  手写 storage key「my_key」  → 读写统一走封装方法
  ...
```

## 七、如实告知的局限（信任加分项，建议也放上）

- 建议项基于正则启发式，可能误报（`(a+b)` 分组会被当成方法调用、合法中文键在部分基础库可用），硬红线精度高、可信。
- 无法替代真机验收：未被语法规则覆盖的真机问题仍需真机跑一遍。

导入解压后应得到一个 `miniprogram-redline-audit/` 目录，结构如下，**缺一不可**：

```
miniprogram-redline-audit/
├── SKILL.md                              # 技能主定义（含 frontmatter、执行流程、输出示例、异常处理）
├── scripts/
│   ├── audit-redlines.js                 # 审计主程序（零依赖，node 直接跑，支持 --help / --strict）
│   ├── audit-paths.js                    # 页面四件套完整性 + app.json 注册校验（四级排除机制）
│   └── audit-closure.js                  # 四层交互闭环（导航/事件/数据/孤儿页），业务项经顶部 CFG 配置
├── references/
│   ├── redlines.md                       # 红线知识库（报告里的 [红线X-Y] 按 id 查）
│   ├── fix-examples.md                   # 逐条修复前后代码对照（改哪条抄哪条）
│   ├── faq.md                            # 常见问题：跑不起来 / 报告解读 / 误报漏报边界
│   ├── first-submit-checklist.md         # 首次提审分步清单
```

### v1.2.0 误报治理
1. 修复 `audit-closure.js` 不解析自定义组件：新增 `Component({ methods: {...} })` 方法提取器，此前组件内每个 `bindtap` 都被误报"方法不存在"（自定义组件事件本就挂在 `methods` 上）。
2. `audit-paths.js` 新增四级排除机制，消除孤儿页误报：内建忽略目录（含 `.codebuddy`）、项目根 `.redlineignore`（支持目录名 / 相对路径前缀 / `foo*` 通配）、命令行 `--ignore=a,b,c`、`<include>`·`<import>` 引用的模板片段自动识别（按实际引用关系判定，不依赖文件命名约定）。
3. 孤儿页由「建议」升级为「阻断」：排除噪音后该项具备判定力，真漏注册会被拦下；扫描摘要输出排除规则数与片段数，便于核对是否排除过度。
4. 文档：SKILL.md「附加独立脚本」「文件索引」与本文件卖点 / 包内清单同步更新。
