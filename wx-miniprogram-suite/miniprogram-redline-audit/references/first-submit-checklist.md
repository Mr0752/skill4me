# 首次提审 / 上架 Checklist（通用版）

> 按“现在就能做 / 提审前必须做 / 上架后才能做”三档排序。项目专属数值（包体大小、具体 env id）请替换成你自己的。

## 一、现在就能做（不需要上架）
| 事项 | 说明 |
| --- | --- |
| **真机验收** | 用开发版/体验版在真机上跑（不需要上架）。这是最大的缺口——模拟器通过 ≠ 真机通过。 |
| **小程序备案** | 工信部备案，**未备案无法发布**。现在就能提交，审核要几天到十几天，越早越好。 |
| **类目选择** | 选与业务匹配的类目；类目决定能用哪些订阅模板、要不要资质。 |
| **隐私指引配置** | MP 后台 → 设置 → 用户隐私保护指引。用到**剪贴板**（备份/恢复）、位置、相册等，必须如实勾选并审核通过。 |
| **云开发部署** | 云环境已配即可随时部署，不受上架限制（若用了云开发）。 |
| **账号信息** | 小程序名称、简介、头像；简介用定稿文案（≤120 字，讲清帮用户解决什么）。 |

## 二、提审前必须做
1. **关闭演示/调试开关**（如 `DEMO_MODE=false`）：避免“点了不付钱就开通”= 绕开虚拟支付 = 拒审。
2. **体验版全流程走一遍**：新用户冷启动 → 引导 → 核心操作 → 看结果 → 导出 → 切换数据 → 删除。
3. **确认没有“假成功”**：任何按钮点下去，若功能没真做，不能显示成功。
4. **版本号**：首次发布用 `1.0.0`；版权年份用首次发布年。
5. **压缩开关**：`project.config.json` + `project.private.config.json` 两处都已 true。
6. **包体**：主包 + 分包均在限制内（主包 2MB、总包 20MB，分包按规则）。
7. **测试账号**：若有登录态相关功能，提交审核时提供测试账号。

## 三、上架后才能做
| 事项 | 说明 |
| --- | --- |
| **虚拟支付开通** | MP 后台 → 虚拟支付，需小程序**已发布后**申请。企业主体可开，个人主体现在也已开放，按流程走。 |
| 补支付参数 + 道具 | 开通后在配置里填 offerId，后台建对应道具；云函数环境变量补齐。 |
| 退役演示开关 | 支付接通后，演示/“即将开通”分支自然不再触发。 |

## 四、提审版为什么是“即将开通”而不是“已能开通”
不是因为主体开不了，而是因为**虚拟支付需要小程序先发布才能申请开通**。首次提审时支付尚未接通，若点“立即开通”却直接开通成功（不付钱、不调支付），属于**绕开虚拟支付**，是拒审风险——这才需要把按钮写成“即将开通”。上架开通虚拟支付后，补上参数与道具，按钮自动恢复。

## 五、建议执行顺序
1. 现在：**提交备案**（耗时最长，先启动）。
2. 同时：**真机验收**（开发版即可，最快发现体验问题）。
3. 同时：**配隐私指引 + 选类目**。
4. 提交审核前：确认演示开关关闭、版本号、简介、头像。
5. 上架后：确认主体 → 能开虚拟支付就接，不能走备用方案。
