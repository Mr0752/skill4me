# 常见问题 FAQ（跑不动 / 看不懂报告 / 误报时先查这里）

## 一、跑不起来类

### Q1：`node: command not found` / `无法将"node"项识别为 cmdlet`
脚本零依赖，只要本机装了 Node.js 即可。检查：`node -v`（v12+ 都能跑）。
没装去 https://nodejs.org 装 LTS 版；或者把脚本放到任何一台有 node 的机器/CI 里跑。

### Q2：报错 `错误：目录不存在 -> xxx`
传入的路径不对。要传**小程序源码根目录**（含 `app.json` 的那一层），不是 `dist`/`build` 产物目录，也不是微信开发者工具的项目目录（里面才有 `miniprogram/` 源码子目录，那就传 `miniprogram`）。
一次扫多个目录（如云函数目录）用空格分隔：`node audit-redlines.js miniprogram cloudfunctions`。

### Q3：输出「审计完成：0 个 JS + 0 个 WXML」什么都没报
说明扫到了目录但里面没有源码。检查三件事：
1. 目录是否传对（见 Q2）；
2. 源码是否在子目录里（应传子目录，或把多个子目录都传进来）；
3. 是否被 `node_modules` / `miniprogram_npm` / `.git` / `.codebuddy` 这些默认跳过目录挡住了。

### Q4：报告某文件「跳过无法读取的文件」
该文件编码不是 UTF-8 或被占用。把文件另存为 UTF-8 再跑；跳过不影响其余文件的结果。

### Q5：退出码有什么用？怎么接 CI？
`0` = 硬性红线清零（建议项仍需人工看）；`1` = 有硬性红线必须修；`2` = 参数/目录错误。
CI 里可直接 `node audit-redlines.js miniprogram || exit 1` 当提交闸门。

## 二、看报告类

### Q6：「硬性红线」和「建议复核」什么区别？都得多吗？
- **硬性红线**：由语法规则精确判定（真机不兼容语法、navigateTo/redirectTo 跳 tabBar、`wx:key="index"`、语法错误），**必须修到清零**——它们导致真机白屏/静默失败。
- **建议复核**：正则启发式，可能有误报，**结合上下文人工确认**后再修。两者都在报告里分好组了。

### Q7：报告里的 `[红线X-Y]` / `[务必3-1]` 是什么？
对应 `references/redlines.md` 里的红线条目编号，去那里看完整背景和事故来源；怎么一行行改见 `references/fix-examples.md` 的前后代码对照。

### Q8：修完怎么看结果？
复跑同一条命令，硬性红线条数会变少；退出码从 1 变 0 即清零。建议每次只修一类，修完即跑，方便定位。

## 三、误报 / 漏报类

### Q9：建议项说我「疑似方法调用 / 中文键」，但实际不是
`--strict` 里的 WXML 规则是实验性的：`(a+b)` 这类括号分组会被当成方法调用；中文键在部分新基础库可用。确认没问题就在心里划掉即可，或去掉 `--strict` 只跑默认高精度规则。
如果没加 `--strict` 还出现这两条，检查命令行参数。

### Q10：明明写了 `clearInterval` 还是报「setInterval 未清理」
该检查要求**同一个文件里**同时出现 `setInterval` 和 `clearInterval`。如果你的清理写在别的文件（如 mixin/基类），属于设计可接受，人工确认后忽略；更推荐把句柄和清理放同一页面，`onHide`/`onUnload` 双保险。

### Q11：它查不出什么？（能力边界，如实告知）
- 只做静态扫描，**不能替代真机验收**：canvas 层级、键盘遮挡、真机白屏里与语法无关的部分（如基础库 bug）扫不到。
- 不执行代码，运行期才暴露的竞态、云端脏数据（红线1-3/1-4）只能靠 `references/redlines.md` 人工对照。
- 只认 JS / WXML 后缀；wxs、自定义框架文件不扫。

## 四、机制类

### Q12：tabBar 判定依据是什么？app.json 解析失败会怎样？
脚本会找到目录里（含子目录）的 `app.json`，读取 `tabBar.list[].pagePath` 做**交叉核查**——所以 `navigateTo` 跳 tabBar 能自动判定，不用你传列表。`app.json` 解析失败只会跳过这一项核查，不影响其他检查。

### Q13：会不会把我的代码上传/联网？
不会。脚本完全本地运行，零网络请求、零第三方依赖，只读你指定目录下的 `.js` / `.wxml` 文本。
