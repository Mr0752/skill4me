# 小程序上架与提审：分步操作指引（小白版）

> **用法**：从上往下照着做，每步做完看「✅ 成功标志」，没看到就别往下走。
> 带 ⚠️ 的是**驳回高发项**，宁可多花五分钟也不要跳。
> 括号里的真实值来自「建筑全过程助手」项目，新项目请替换成你自己的。

---

## 阶段 0 · 出发前准备

### 步骤 0.1 —— 确认主体与认证状态
- **去哪儿**：MP 后台（mp.weixin.qq.com）→ 设置 → 基本设置
- **做什么**：确认主体类型（个人 / 企业）、微信认证是否在有效期内
- **✅ 成功标志**：认证状态为「已认证」且有效期 > 3 个月
- **⚠️ 易翻车**：微信认证有效期 1 年，过期会导致支付/部分接口不可用；到期前 3 个月会收到年审通知

### 步骤 0.2 —— 跑本地代码体检（全绿才继续）
- **去哪儿**：项目根目录，命令行
- **做什么**：依次执行项目 `doc/新项目复用资产清单.md` 二 B 节里的脚本
- **✅ 成功标志**：全部退出码 0，且**扫描样本数与预期一致**
- **⚠️ 易翻车**：**退出码 0 ≠ 真的通过** —— 若某个文件压根没被扫到，脚本也会"全绿"。必须对比样本数，防「文件被跳过」的假绿。

### 步骤 0.3 —— 准备提审材料
- **做什么**：准备 ① 功能截图（核心页面 3~5 张）② 应用简介 ③ 演示视频（可选但推荐）④ 类目资质（涉支付/特殊类目）
- **✅ 成功标志**：材料齐全，截图能看清核心功能

## 阶段 1 · 账号设置

### 步骤 1.1 —— 设置名称 / 头像 / 简介
- **去哪儿**：管理 → 账号设置
- **做什么**：填写小程序名称、上传头像、写简介
- **✅ 成功标志**：三项均有内容且符合品牌口径
- **⚠️ 易翻车**：**名称一年仅 2 次修改机会**，头像 2 次/年，简介 5 次/月 —— 定稿前想清楚；名称与其他小程序重名会被驳回

### 步骤 1.2 —— 配置服务类目
- **去哪儿**：管理 → 账号设置 → 服务类目
- **做什么**：选择与**实际功能一致**的类目（本项目：工具 > 办公 / 计算器）
- **✅ 成功标志**：类目与功能匹配，涉及付费的类目已具备相应资质
- **⚠️ 易翻车**：类目与实际功能不符是**头号驳回原因**；涉支付类目需额外资质

### 步骤 1.3 —— 开通客服
- **去哪儿**：功能 → 客服
- **做什么**：开通并绑定客服微信号
- **✅ 成功标志**：客服状态为「已启用」
- **⚠️ 易翻车**：提审会看响应能力，无客服可能被视为服务缺失

---

## 阶段 2 · 服务内容声明 ⚠️ 驳回高发

### 步骤 2.1 —— 用户隐私保护指引
- **去哪儿**：账号设置 → 服务内容声明 → 用户隐私保护指引 →「更新」
- **做什么**：勾选产品**实际调用**的隐私接口，并填写使用目的
- **✅ 成功标志**：状态变为「**已更新**」
- **⚠️ 易翻车**：
  - 声明的接口必须 **⊇ 代码实际调用的**，漏一个真机就报 `errno 112 api scope is not declared`
  - **别多勾**：声明了却不用的接口同样是风险（多勾 = 多一份解释义务）
  - 本项目固定 6 项：位置信息、摄像头、选中的照片或视频、相册（仅写入）、剪贴板、手机号
  - **严禁勾「用户信息（昵称/头像）」** —— 平台整改红线

### 步骤 2.2 —— 同一页还需确认的字段
- **存储期限**（5.1）：**不要留 0**，填 365（工程数据保留一年属合理最短）
- **变更告知方式**（5.2，必填）：填「弹窗提示」
- **开发者联系方式**：填常用邮箱
- **底部声明勾选框**勾上 → 点「确认并提交」

### 步骤 2.3 —— UCG 用户生成内容声明 ⚠️ 有 AI 生成必填
- **去哪儿**：服务内容声明 → 用户生成内容场景声明 →「更新」
- **做什么**：勾选☑ 文本；场景含「AI 生成 / 智能生成内容」；内容安全机制选「使用平台建议的内容安全API」
- **✅ 成功标志**：状态为「已更新」
- **⚠️ 易翻车**：只要产品内有大模型生成内容（如草稿/文书/问答），**不声明提审必驳回**

### 步骤 2.4 —— 订单中心 path（虚拟支付必须设）
- **去哪儿**：服务内容声明 → 小程序订单中心 path →「设置」
- **做什么**：填订单列表页路径（本项目 `pages/orders/orders`）
- **✅ 成功标志**：状态变「已设置」
- **⚠️ 易翻车**：**不要填 vip/会员页** —— 订单中心是支付订单列表，填错会让审核员找不到订单

## 阶段 3 · 开发设置

### 步骤 3.1 —— AppSecret
- **去哪儿**：开发 → 开发管理 → 开发设置
- **做什么**：生成 AppSecret → 写进云函数环境变量 `WX_APPSECRET`
- **⚠️ 易翻车**：不落代码库、不发聊天；只存云端环境变量

### 步骤 3.2 —— 服务器域名
- **做什么**：用云开发 → 点「立即开通」免配

### 步骤 3.3 —— 消息推送
- **做什么**：选「云函数托管」最省事（发货回调要用到）

## 阶段 4 · 虚拟支付 ⚠️ 顺序关键

> **顺序错了必然返工：必须先让小程序上架成功，才能申请虚拟支付。**
> 因此首次提审时**支付功能先不接**，但要给「即将开通」状态，否则被判"绕开虚拟支付"驳回。

### 步骤 4.1 —— 记 OfferID + 生成 AppKey
- **去哪儿**：支付与交易 → 虚拟支付 → 基本配置
- **做什么**：记下 OfferID（本项目 `1450672748`）；分别生成**沙箱 AppKey**（先测）和**现网 AppKey**（上线）
- **⚠️ 易翻车**：沙箱/现网 AppKey 别混用；不要长期明文留在聊天记录

### 步骤 4.2 —— 配云函数环境变量
- **做什么**：写入下表（用 `tcb fn deploy`，**不要**用 DevTools CLI，后者会静默跳过 envVariables）

| 函数 | 变量 |
|---|---|
| `entitlement` | `VP_OFFER_ID`、`VP_APPKEY`、`VP_ENV`（沙箱=1 / 现网=0）、`WX_APPID`、`WX_APPSECRET`、`VP_CALLBACK_SECRET` |
| `payNotify` | `VP_CALLBACK_SECRET`（**必须与 entitlement 同一把**，否则钱付了权益发不出） |

- **✅ 成功标志**：`tcb fn env pull` 能看到变量；部署后从文件中移除密钥

### 步骤 4.3 —— 道具配置
- **去哪儿**：虚拟支付 → 开发版本 → 添加道具
- **做什么**：**道具 ID 必须与代码 `GOODS`/`PLANS` 的 `id` 逐字一致**
- **⚠️ 易翻车**：
  - **漏建 = 用户点购买撞"未知的商品"死路**。本项目曾「代码要求 13 个，后台只有 11 个」，缺 `doc_ai_deliver`、`doc_witness`。
  - 以**代码字段为准**（`disabled:false` = 必须建），别以文档为准。
  - 名称避开「·」「+」等特殊字符，可用「-」。
  - 全部价格 ≥ 1 元（满足 iOS Apple 支付最低限制）。

### 步骤 4.4 —— 发货推送配置
- **去哪儿**：虚拟支付页面底部绿色「前往配置」
- **做什么**：推送模式选「云函数」；消息类型 `event`；事件类型 `xpay_goods_deliver_notify`；环境 + 云函数 `payNotify`
- **✅ 成功标志**：在「开发管理 → 消息推送」能查到该配置
- **⚠️ 易翻车**：`VP_CALLBACK_SECRET` 必须先写进两个函数，否则推送被 `forbidden` 拒绝

### 步骤 4.5 —— 沙箱全流程验证
- **做什么**：下单 → 服务端签名 → 拉起支付（沙箱不真扣钱）→ 发货推送到达 `payNotify` → **查云数据库确认 `ent_users` / `xpay_orders` 状态为 `delivered`**
- **✅ 成功标志**：**以云端数据为准，不靠界面感觉**

### 步骤 4.6 —— 切现网
- **做什么**：`VP_ENV` 切 `0` + 换现网 AppKey → 道具「批量发布」到线上版本 → 真机再走一单小额验证

## 阶段 5 · 上传代码与提交审核

### 步骤 5.1 —— 上传代码
- **去哪儿**：微信开发者工具 →「上传」
- **做什么**：填版本号与项目备注（**写清本次更新点**）
- **✅ 成功标志**：MP 后台「版本管理」出现该版本

### 步骤 5.2 —— 提交审核
- **去哪儿**：管理 → 版本管理 → 开发版本 →「提交审核」
- **做什么**：填写测试信息
- **⚠️ 易翻车**：
  - **无登录体系的项目：测试账号/密码务必清空**，在备注说明即可（填了反而让审核员登不上）。
  - 备注册例：「本小程序无需注册登录，微信授权后即可使用全部功能」。

## 阶段 6 · 提审后跟踪与驳回应对

- **去哪儿**：版本管理 → 审核版本 / 审核状态
- **跟踪**：关注审核状态变化与「通知中心」的审核结果

### 驳回四项高发（按出现频率）
| 原因 | 表现 | 怎么改 |
|---|---|---|
| **类目不符** | 功能与所选类目不一致 | 改类目或调整功能范围 |
| **隐私声明缺失** | 漏勾隐私接口 / 状态非「已更新」 | 重做 2.1，确认状态 |
| **支付绕开虚拟支付** | 引导线下/普通支付，或提审版支付未接且无提示 | 走虚拟支付；未接时给「即将开通」 |
| **文案承诺过度** | 宣传了不存在的能力 | 按「文案=承诺」删改 |

### 应对纪律
1. 逐条对照「拒绝原因」原文改，**不要只改表面现象**。
2. 改完**重跑阶段 0 的全套审计脚本**，全绿再提交。
3. 在「更新说明」里写明本次针对驳回做了什么修改，帮审核员快速复核。
