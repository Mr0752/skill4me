# 小程序开发通用红线（去项目化版）

> 适用：微信小程序（含云开发）。每条都来自真实踩坑。标记：[红线]=违反即出事；[务必]=强烈建议，否则迟早出事。
> 文中 `app.S/app.L`、`lockClick`、`goPage` 等是“你项目里的统一封装方法”的代称，照你自己的实现替换即可。

---

## 1. 云开发 / 云函数（最贵、最隐蔽，第一重点）

[红线] 1-1 后台同步/轮询**禁止固定短间隔盲轮询**，必须“事件驱动 + 无变化退避”
- 事故：`setInterval(15s)` 每轮无条件 pull，开着模拟器一天烧 4.2 万次云函数调用；免费额度 20 万/月只够开 5 天，上架后每个真实用户都这样烧。
- 正确做法：同步节奏交给**递归 setTimeout + 空闲退避**：基础间隔 60s；连续 N 轮无本地变更 → 退避到 5 分钟。本地有写入（抬高版本号）立即唤醒快节奏；切回前台（onShow）立即拉一次。记账/非实时协作场景，快模式 2~3 分钟、空闲 10 分钟足够。
- 额度自检：云函数**调用次数**（20 万/月）是唯一会爆的免费资源；容量/存储/流量几乎不会超。架构阶段就要算这笔账。

[红线] 1-2 所有“出站到云端”的数据**必须在唯一出口统一清洗**
- 云数据库**禁止空字段名**。墓碑/分桶时 key 为空的记录会进 `''` 桶，原样上传 → 服务端 `-502001 empty field name`，整次失败。
- 只修一条通道=修一半：`push`/`merge`/备份导出都要过同一清洗函数（剔除空桶、`undefined`、空字符串）。改完用 grep 核对所有出站 payload 组装点。

[红线] 1-3 云端返回的值**一律当不可信，读取处统一数字化**
- 事故：本地被清掉的数值，pull 用云端脏值（非数字）覆盖回来，`toFixed` → 整页崩。
- 规则：所有从云/备份回读的数字键，读取处必须 `Number(x)` + `isFinite` 兜底回退默认值。别只信写入端干净——云端可能存着历史脏值，且 pull 会把它合并回本地。

[红线] 1-4 演示数据 / 初始化数据**必须幂等**
- 事故：重导演示数据用“快照+叠加”，每次生成新 id 推上云；清本地却没把墓碑推上云 → 云端只增不减，本地清掉的脏数据被 pull 复活。
- 规则：重导必须“先清本地再写”且**清云与清本地同一事务**；演示/初始记录用**固定 id**，重导不产生新脏数据。

[红线] 1-5 共享缓存层内部状态**只能重置 `{}`，绝不置 `null`**
- 事故：`_cache=null` 导致 `key in _cache` 抛 `Cannot use 'in' operator ... in null`，把自动同步循环里所有读存储全打崩。
- 规则：缓存层归零必须 `={}`；`L/S` 入口加 `if(!_cache||typeof!=='object')_cache={}` 兜底——外部谁误置 null 也不会打崩全 app。

[务必] 1-6 上线前留一个**云同步一键关闭开关**
- 常量如 `CLOUD_DISABLED`（调试期 true → 云能力完全不初始化；上线前必须改 false）。用途：调试省额度 + 出事时快速止血。注释写清“上线前必须改回”。

[务必] 1-7 压测/调试时**盯云控制台“资源使用”页**，别只看 IDE 控制台
- IDE 控制台能看到日志刷屏，但看不到调用量数字；配额消耗是 B 类坑，只有云后台可见。任何后台定时任务上线前，先开着跑一天看曲线。

## 2. 真机兼容性红线（A 类，模拟器测不出）

[红线] 2-1 禁用 `?.` / `??` / `||=` / `&&=`
- 真机基础库 Babel 不转换这些运算符 → 真机直接 `SyntaxError` 白屏；模拟器、lint、IDE 全不报。
- 等价写法：`a?.b` → `(a||{}).b`；`a ?? b` → `(a==null?b:a)`；`a ||= b` → `a = a || b`；`a &&= b` → `a = a && b`。
- 对象展开 `{...x}` 可放心用。数字分隔符 `1_000` 也不行，去掉下划线。

[红线] 2-2 代码压缩开关**两处都要 true**，禁止手改源码“压缩”
- `project.config.json` 与 `project.private.config.json` 的 `minified/minifyWXML/minifyWXSS/es6/postcss` 都要开；JS 压缩只在**上传时**生效。手改源码做“压缩”= 维护灾难，禁止。

## 3. 数据层 / Storage

[务必] 3-1 统一封装的存储读写**自动加前缀**，别在 key 里手写前缀
- 手写前缀会和自动前缀叠加成 `xx_xx_`，数据静默写不到也读不出。读写统一走你封装的 `S(key)` / `L(key, def)`。

[务必] 3-2 遍历键表逐键判断类型再操作
- 键表里混有数字型和对象型键，不判类型直接 `.forEach` 会崩。备份/清理/复制账套遍历必须逐键守卫（如 `Array.isArray`）。

[红线] 3-3 写操作的辅助方法**禁止引用调用方局部变量**
- 外层 try/catch 会吞掉 `ReferenceError` → 一半成功一半静默失败，极难排查。辅助方法只依赖入参与全局状态。

[务必] 3-4 算钱/算账口径**只在全局有一份实现**
- 所有“算利润/折算/剩余/到期天数”的函数只在 `app.js` 或单一模块有一份实现，页面只读不另算；多处显示同一数字必须同源，否则用户拿计算器一对就对不上。

## 4. 交互 / 视觉红线

[红线] 4-1 写操作统一**防重复提交锁**，同一表单的多个提交入口**共用同一把锁**
- 两把不同锁 = 交替连点能开出两笔一样的单。连续提交场景锁时长要兼顾（如 600ms）。

[红线] 4-2 **禁止在 `wx.showModal` 的 success/complete 里同步再弹 modal**
- 前一个未关完，第二个静默失败，表现为“点了没反应”。必须 `setTimeout ≥300ms` 延后弹。

[红线] 4-3 弹层内 canvas（二维码等）**禁止和固定按钮排同屏挤压**
- 原生同层组件在“滚动区末尾 + 固定 foot”夹缝处，部分机型会浮到按钮上层盖住它。多步流程用分步视图，canvas 跟随该步 `wx:if` 渲染，进入该步时在 `setData` 回调里重画。

[务必] 4-4 浮层/气泡高度**用 `createSelectorQuery` 实测**，不按文案行数估
- 估小了按钮会被 tabbar/手势条挡住。底部目标气泡优先放上方，预留安全区高度（约 56rpx/px）。

[务必] 4-5 单行 `<input>` 必须同时给 `height` 与**同值 `line-height`** + `text-align:left`
- 只给 height 或不给，文字会贴边/不居中。页面级 wxss 覆盖全局 input 样式时必须显式覆盖全局 `padding`。

[红线] 4-6 导航只走**封装的导航方法**；**禁止两段式导航**（先切中间页再二次跳）
- TabBar 不能带 query，跨页传参用 Storage 键。自定义返回一律不加（`reLaunch` 会刷新导航防抖，谨慎用原生 `wx.reLaunch`）。

## 5. 文案红线（对外承诺 = 实现）

[红线] 5-1 没有的功能**不许写**进介绍/按钮
- 无真 PDF、无打印 API → 禁止“导出 PDF”“支持打印”；云能力只在云就绪为真时可承诺；本地模板能力不得写成“云端处理”。用户发现货不对板=信任崩塌。

[务必] 5-2 术语/品牌全站统一
- 品牌名、会员档位叫法、业务术语一处定义，全站复用，禁止各页面自留一份。

## 6. 提审 / 上架红线

[红线] 6-1 虚拟支付需**小程序先发布**才能申请
- 首次提审版支付未接通，必须有关闭真实支付的“演示/即将开通”开关（如 `DEMO_MODE=false`，按钮“即将开通”），否则点了不付钱就开通 = 绕开虚拟支付 = **拒审**。
- 企业主体可开通虚拟支付（个人主体现在也已开放，别再拿主体当阻断理由）。企业主体可用原生客服 `open-type="contact"`。

[务必] 6-2 价格/档位/配置若**多处定义，必须同步**
- 例如客户端价格表 + 云函数价格表 + 后台道具价，漏一处=服务端二次校验拒发货。改动时同步所有定义点。

---

## 7. 工程纪律（交付前必跑）

[务必] 7-1 提交前跑回归闸门脚本
- 语法/路径/导航绑定/Storage 键闭环/演示数据核算脚本。改 wxml 绑定或导航必跑交互审计；改演示常量或口径必跑数据核算。

[红线] 7-2（AI 协作纪律）验证 bug **先核实磁盘代码，不甩锅运行环境**
- 看到“模拟器还在跑旧代码”“你环境有问题”这类推断，先确认磁盘上修复是否在、再下结论。把代码层面 bug 归咎于运行环境，会掩盖真问题、延误修复。
- 风险要在**设计阶段算账**（如“15s 轮询 × 24h × 用户数 = 多少额度”），不要等用户从云后台发现。
- 代码里已有的异常日志（如每轮“同步完成”刷屏）是**信号**，主动追因，不要当成正常噪音放过。

## 8. WXML 编译期硬约束（写了就静默失效 / 或编译直接报错）

[红线] 8-1 `{{}}` 内不支持方法调用、不支持动态绑定处理函数名
- 所有派生值（视觉映射、合计、进度、类名）**必须在 JS 里预计算成字段**，wxml 只绑定字段。
- 动态方法统一走 `onMainAction` 这类 switch 入口（`bindtap="onMainAction"` + `data-action`），不要写 `bindtap="{{item.fn}}"`。

[红线] 8-2 `{{}}` 内慎用中文属性名
- `{{counts.待派单}}` 这类中文键在**部分基础库**会编译报错或行为异常（模拟器/本机能过 ≠ 真机稳）。为兼容性，所有带中文的键必须预计算成 ASCII 字段（如 `counts.pending`）。

[红线] 8-3 `wx:key` 不能写 `"index"`
- 会被当属性名（item 上没有 `index` 属性）→ 等于没 key，列表更新错乱。列表无唯一字段时，在渲染数据里生成 `_k`（如 `'sku'+idx`），且不要写进 storage。

[红线] 8-4 WXML 没有 `<b>` 组件
- WXML 不是 HTML，未知标签在**部分基础库**会被静默忽略（文字不加粗）或严格模式报错。加粗一律 `<text class="b">…</text>`（`.b{font-weight:800}`）。

[务必] 8-5 sitemap.json 官方已下线
- `app.json` 不再声明 `sitemapLocation`，`project.config.json` 不再保留 `checkSiteMap`。

## 9. 小程序平台能力约束（导入/导出 / 跳转 / 原生组件 / 样式）

[红线] 9-1 跳转 tabBar 页面必须用 `wx.switchTab`
- `navigateTo` 跳 tabBar 页面会**静默失败**（不报错但页面不动）。跳转前先查 `app.json` 的 tabBar 列表决定用哪个 API。统一走项目封装的 `goPage` 类方法，禁止页面里手写 `wx.navigateTo/switchTab`（只有清缓存重启用 `wx.reLaunch`）。

[红线] 9-2 文件导入/导出的平台边界
- **导入**：`wx.chooseMessageFile` 让用户从聊天/文件 App 选文件（Excel/CSV/txt/PDF），拿临时路径后用 `wx.getFileSystemManager()` 读；表格用 `xlsx.mini` 前端解析，无需后端。⚠️ iOS 只能读「文件」App 共享给微信的文档。
- **导出**：手机端**不能**直接写系统 Download 目录，生成文件默认在小程序沙盒，别的 App 看不到。正确做法：前端生成 → `wx.openDocument()` 唤起预览 → 用户在预览页转发/存文件助手。**PC 端微信小程序**有专属 `wx.saveFileToDisk`，可直接「另存为」到电脑磁盘，体验最好。

[红线] 9-3 原生组件 input/textarea 禁止垂直 padding
- 会裁字。用固定 `height` + 水平 `padding` 控高。带 fixed 底部导航的页面尾部必须放安全占位 view，否则最后一段内容滚不出来。

[务必] 9-4 全局 wxss 类新增前先 grep
- `app.wxss` 是全局类总库，新增类名前先 grep 是否已存在，避免同名双定义互相污染样式。

[务必] 9-5 `flex` 简写里禁止用 `calc()`
- `flex: 1 1 calc(50% - 8rpx)` 在真机上整条声明失效，卡片变成一行一个。栅格统一：容器 `display:flex;flex-wrap:wrap;justify-content:space-between;`，子项 `width:48.5%;flex:none;`。`width:calc(...)` 安全；`gap` 在老 WebView 不可靠，栅格别依赖它。

## 10. 运行期性能 / 生命周期红线

[红线] 10-1 `setData` 禁止整页 / 大对象
- `setData(this.data)` 或一次塞几十个顶层键，会把整个数据树 JSON 序列化再 diff，列表/大页必卡顿掉帧。只传**变化的字段**；列表项更新用路径式 `setData('list[' + i + '].x', v)` 增量。
- 自检（审计器）：首参对象字面量顶层键 ≥ 12 即标“疑似大对象”。

[红线] 10-2 定时器必须 `onHide` / `onUnload` 清理
- 把 `setInterval/setTimeout` 句柄存到 `this` 上，却不在 `onHide`、`onUnload` 调 `clearInterval/clearTimeout` → 页面切后台仍在跑：后台反复拉取烧云额度（叠加红线1-1）、定时器堆积致闪退。有定时器但全文无 clear 即为确定泄漏。

[红线] 10-3 禁止直接赋值 `this.data.xxx`
- 直接改 `this.data` 不刷视图，且下次任意 `setData` 会用旧视图树**回滚**你的改动，表现成“改了又变回”。一律 `this.setData({ xxx: val })`。
